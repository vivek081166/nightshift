## 7. Operational reminders and reference links

For quick reference during your shift, keep the standard tools and handbook locations pinned:

- **Incident coordination:** `#inc-live` in chat. Remember: open a thread for any P1 or P2, paste the alert line directly at the top, and log the first move before undertaking multi-minute diagnostics.
- **Dashboards:** Folder "Sorrel / Services" on the metrics tool:
  - Web: "Sorrel / web" (watch 5xx, p95 load times, edge CDN errors, node disk usage).
  - API: "Sorrel / api" (watch endpoint latencies, DB pool saturation, audit log writes, partner rejection rates).
  - Payments: "Sorrel / payments" (watch checkout submission failures, provider timeout vs. local latency, duplicate refund counts).
  - Notifier: "Sorrel / notifier" (watch queue depth vs. delivered per minute, vendor response codes, duplicate message detection).
- **Logs:** Index `sorrel-prod-*`. Always narrow search windows to the exact alert onset to conserve search cluster capacity. Common error filters:
  - `service=web level=ERROR`
  - `service=api msg="pool exhausted"`
  - `service=payments outcome=failed`
  - `service=notifier msg="vendor error"`
- **Handbook first moves:** As a reminder, apply only one of the five approved first moves:
  1. *roll back:* When a recent deploy of that service is the direct cause.
  2. *read logs:* When nobody knows yet what happened.
  3. *check provider:* When the alert itself indicates an outside service dependency issue.
  4. *page owner:* When an irreversible state has occurred (money moved incorrectly, data exposed, credentials leaked, accounts deleted) or when an unpermitted decision must be made.
  5. *no action:* When no customer impact is present and no system has failed.
